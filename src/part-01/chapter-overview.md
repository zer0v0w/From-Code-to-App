# Chapter 1: First Contact with Programming and Dart

The goal is comfort, not completeness. Students should become willing to change code, run it, inspect the result, and recover from mistakes. Dart is the language from the beginning so the transition to Flutter does not require learning a second syntax.

## Session sequence

| Session | Core idea | Visible outcome |
|---|---|---|
| 1. First contact with code | Values, variables, types, basic input/output, run/re-run | Change `apple` to `orange` and observe output; finish with a prepared live-UI bridge |
| 2. Operations and calculator | Expressions, operators, simple functions and return values | A calculator whose behavior students can modify |
| 3. Decisions and loops | Boolean logic, branching, repetition | Small playful programs with different outcomes |
| 4. Collections and problem-solving | Lists, maps, functions with collections, debugging | A tiny catalogue/score tracker and a debugging homework task |
| 5. Dart fundamentals and OOP | `var`, `final`, `const`, `late`, null safety, functions, classes/objects | Read and modify small Dart models without treating syntax as magic |
| 6. Revision and async | Consolidation, useful list/map operations, `Future`, `async`/`await` | Students explain earlier concepts and recognize an asynchronous operation |

Plan roughly two hours per session. Session 5 is dense; keep OOP to classes, fields, constructors, and methods. Move inheritance, abstract classes, and advanced language features to optional reading.

## Teaching principle

Keep returning to the same activity: **predict → change → run → explain**. Early code should be small enough that the student can understand all of it at once. The first assignment is not meant to be impressive; it is meant to show that the student can use the basics independently.

## Readiness check

Before moving to Flutter, each student should be able to:

- Write a short Dart program with variables, conditions, loops, a function, and a collection.
- Explain the difference between changing a value and changing the code's logic.
- Find and fix at least one syntax or logic error.
- Explain what a nullable value means at a basic level.
- Create and use a simple class, even with notes available.

If many students cannot do these things, reduce the Chapter 1 assignment rather than pushing forward because the calendar says so.
